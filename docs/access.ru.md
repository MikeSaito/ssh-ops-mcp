# Настройка доступа и подключений

Установите Node.js 22.13+ и выполните `npm ci`. Подключения и секреты храните вне репозитория. Установка не меняет настройки клиента или существующие ACL.

## Проверка окружения

```sh
node -- bin/ssh-ops-mcp.js --servers-file /absolute/private/servers.json --doctor
node -- bin/ssh-ops-mcp.js --servers-file /absolute/private/servers.json --check-config
node -- bin/ssh-ops-mcp.js --servers-file /absolute/private/servers.json --print-client-config
```

По умолчанию doctor проверяет только локальный компьютер: Node, SQLite, настройки, права файлов подключения, существующего состояния и доступность родительского каталога для записи. Он не создаёт отсутствующее состояние и не выводит пароли, ключи или passphrase. Отсутствие проверки ключа сервера отмечается предупреждением.

Подключение проверяется только явно:

```sh
node -- bin/ssh-ops-mcp.js --servers-file /absolute/private/servers.json --doctor --connect --server-id staging
```

Проверяются SSH-вход, ключ сервера, Linux, Python 3.8+, bash, необязательный sqlite3 и открытие SFTP. Файлы сервера не меняются. При ограничениях доступа для этого нужен `ssh_server_info`. Ошибка обязательной проверки возвращает код 1.

Для одного подключения используйте `--connection-file FILE`. Старый `--env-file` поддерживается через `node -- ENTRY --env-file FILE`: разделитель не даёт Node обработать флаг раньше MCP. Сгенерированная конфигурация клиента содержит пути, без секретов; добавьте её в клиент самостоятельно после проверки.

## Ограничения на один запуск

Создайте приватный файл политики вне репозитория:

```json
{
  "version": 1,
  "servers": {
    "prod": { "tools": ["ssh_server_info", "ssh_file_hash", "ssh_read_file"] },
    "staging": { "tools": ["ssh_server_info", "ssh_exec", "ssh_file_hash", "ssh_edit_file"] }
  },
  "transit_servers": []
}
```

```sh
node -- bin/ssh-ops-mcp.js --servers-file /absolute/private/servers.json --policy-file /absolute/private/access-policy.json
```

Вместо флага можно задать `SSH_MCP_POLICY_FILE`. Для старого режима одного сервера ID равен `default`. Имена инструментов точные, без `*`; неизвестные и повторяющиеся имена отклоняются. Политика загружается после перезапуска.

Неуказанные серверы скрыты, их файлы подключения не читаются. Инструменты видны, если разрешены хотя бы для одного сервера, но каждый вызов дополнительно проверяется для выбранного ID до SSH. `ssh_servers_list` показывает только разрешённые цели. Без политики сохраняется прежний доступ ко всем настроенным аккаунтам. При запрете очистки скачиваний фоновая очистка не запускается; локальное состояние и аудит могут создаваться и при диагностическом доступе.

Разрешённая shell-команда или запись файлов всё ещё даёт возможности SSH-пользователя. Политика не ограничивает команды, пути и права root. Пользователь, способный менять запуск MCP или локальные файлы, может выбрать другую политику. Настоящее разделение прав обеспечивается аккаунтами и разрешениями на сервере.

## Права файлов

На Unix секретные файлы требуют 0600, существующие каталоги состояния 0700 или строже. Манифест и политика могут быть читаемы другими, но запись посторонним запрещена. Символические ссылки для секретных файлов и корня состояния отклоняются.

На Windows проверяются ACL файла/каталога и прямого родителя. Доверенными считаются текущий пользователь, SYSTEM и локальные администраторы. Чужое чтение секретов, опасные права записи/замены, чужой владелец, null DACL и неподдерживаемые ACE отклоняются. Проверка консервативная: разрешающий ACE не компенсируется запрещающим. Существующие права автоматически не меняются. Это не защита от процесса того же пользователя или привилегированного администратора; используйте доверенный приватный каталог.

## Промежуточный сервер

В `servers.json` задайте маршрут через `via`:

```json
{
  "version": 1,
  "servers": [
    { "id": "jump", "env_file": "jump.env" },
    { "id": "private-app", "env_file": "private-app.env", "via": "jump" }
  ]
}
```

Оба подключения имеют отдельные учётные данные и проверку SSH-ключа. Промежуточный сервер должен разрешать `direct-tcpip` к адресу и порту цели; он же разрешает DNS-имя цели. Поддерживается один переход. Цепочки, циклы, ProxyCommand и чтение `~/.ssh/config` не поддерживаются. При ошибке прямого обходного подключения нет; другие маршруты работают независимо.

Если используется политика, добавьте `"transit_servers": ["jump"]`. Это разрешает промежуточный узел для маршрута, но не открывает его для команд, если его нет в `servers`. Agent forwarding выключен на обоих соединениях.

Прямые подключения сохраняют прежние каталоги и алгоритмы ID. Маршрут через промежуточный узел получает отдельное локальное состояние и ID запросов. При смене узла выбирается другое состояние. На одном физическом SSH-аккаунте удалённые файлы остаются общими; для блокировок используйте одинаковые ресурсы. Фоновый процесс скачивания получает только выбранную цель и необходимый промежуточный узел. Изменение настроек не перенаправляет запущенный процесс.

## Поиск и точечные правки

`ssh_find_files` ищет обычные файлы по `pattern` в абсолютном каталоге `path`. Шаблоны используют Python `fnmatch` для имени или относительного пути. `ssh_search_text` добавляет буквальный `text`, поиск по строкам UTF-8 и необязательный `case_sensitive: false`. Регулярных выражений нет.

По умолчанию пропускаются скрытые и распространённые секретные файлы. Включение задаётся отдельно через `include_hidden` и `include_sensitive`. Поиск не идёт по символическим ссылкам и другим файловым системам. По умолчанию глубина 8, результатов 100; максимумы: глубина 32, 1000 результатов, 10 000 записей, 10 секунд обхода, 1 МиБ на текстовый файл, 16 МиБ входных данных и около 64 КиБ результата. Бинарные файлы и неподдерживаемая кодировка пропускаются. Проверяйте `truncated`, `skipped`, `scanned_bytes`: неполный поиск не доказывает отсутствие файла или текста. Маскирование не гарантирует сокрытия всех секретов.

Для `ssh_edit_file` сначала получите SHA-256, передайте `expected_sha256` и список `edits` с `old_text`, `new_text`, `expected_matches` (по умолчанию 1). Правки выполняются последовательно над оригиналом на сервере. По умолчанию `preview: true` показывает diff. После проверки повторите с `preview: false`; при необходимости задайте `validate_command` с `{path}` для проверки временного файла.

Неоднозначная замена, несовпадение хеша, бинарный файл, превышение лимита или ошибка валидации сохраняет оригинал. Сохраняются неизменённые BOM/CRLF, права и владелец; создаётся приватная резервная копия. Максимум 50 правок, 100 совпадений на правку, 5 МиБ результата. Значения `[REDACTED]` не вставляйте обратно.

## Проверки и скорость

`npm run check:install` проверяет установку из чистого архива во временный каталог, требует доступ к npm для зависимостей. `npm run test:real-ssh` запускает изолированные Debian OpenSSH, Alpine OpenSSH и Dropbear в Docker. Порты наружу не публикуются, настройки только тестовые, рабочие серверы не используются. `SSHOPS_TEST_NODE=24` выбирает Node.js 24; по умолчанию 22.

`npm run bench:ssh` измеряет 20 последовательных вызовов: подключение по этапам, helper с новым соединением, опытный helper с сохранённым соединением и полный вызов MCP. Эти локальные результаты нельзя переносить на интернет-соединения. Переиспользование соединений в рабочем MCP не включено: ещё нужны проверки отмены, конкурирующих вызовов и ограничения памяти. Интерактивные сессии и пользовательские туннели отложены до реальной потребности.
